# 部署手册

**适用版本**：v1.0.0
**手册范围**：环境要求、安装步骤、配置文件说明、启动顺序、验证方法、故障排查。

---

## 1. 环境要求

### 1.1 硬件与操作系统

| 项目 | 最低要求 | 推荐配置 |
|------|----------|----------|
| CPU | 双核 x86/ARM | 4 核及以上 |
| 内存 | 1 GB（五节点+Web 同机） | 4 GB |
| 磁盘 | 200 MB（含事件日志增长空间） | 1 GB |
| 操作系统 | Windows 10+ / Linux（Ubuntu 20.04+、CentOS 7+）/ macOS | 任意主流发行版 |

### 1.2 软件依赖

| 软件 | 版本 | 是否必需 | 用途 |
|------|------|----------|------|
| Python | 3.8+ | **必需** | 全部代码运行时 |
| Flask | 2.0+ | Web 控制台需要 | REST API 与页面服务 |
| PyYAML | 5.4+ | 可选 | 配置解析（缺失时自动使用内置解析器） |
| paho-mqtt | 1.6+ | 可选 | MQTT 通道（缺失时自动降级为纯共享内存） |
| Mosquitto Broker | 2.0+ | 可选 | 跨主机部署时的消息中间件 |

> **零依赖模式**：不安装任何第三方库时，五个节点、订单模拟器、故障注入器均可正常运行（纯共享内存通道 + 内置 YAML 解析器）；仅 Web 控制台必须安装 Flask。

### 1.3 网络要求

- 单机部署：无任何网络要求（含完全离线环境）；
- 多主机部署：各主机可达 MQTT Broker（默认端口 1883），节点间无需直连。

## 2. 安装步骤

### 2.1 获取代码并安装依赖

```bash
cd IEC61499-Distributed-Industrial-Control-System

# 安装依赖（推荐；核心功能不依赖其中任何一项）
pip install -r requirements.txt
```

### 2.2 （可选）安装并启动 Mosquitto

```bash
# Ubuntu/Debian
sudo apt install mosquitto && sudo systemctl start mosquitto

# Windows：官网安装后 net start mosquitto
# macOS
brew install mosquitto && brew services start mosquitto
```

不启动 Broker 时系统自动运行于纯共享内存模式，功能完整。

### 2.3 目录初始化

首次运行时 `runtime/` 目录（共享内存通道）会自动创建，无需手工建立。

## 3. 配置文件说明

唯一的配置文件是 `core/nodes.yaml`，分为四段：

### 3.1 `system` 段

| 键 | 默认值 | 说明 |
|----|--------|------|
| name | IEC61499-Distributed-Industrial-Control-System | 系统名（展示用） |
| runtime_dir | runtime | 共享内存通道根目录（相对项目根） |
| log_level | INFO | 日志级别（DEBUG/INFO/WARNING） |

### 3.2 `mqtt` 段

| 键 | 默认值 | 说明 |
|----|--------|------|
| enabled | true | false 时禁用 MQTT 通道（纯单机模式） |
| host | 127.0.0.1 | Broker 地址 |
| port | 1883 | Broker 端口 |

### 3.3 `defaults` 段（集群级参数）

| 键 | 默认值 | 说明 |
|----|--------|------|
| heartbeat_interval_ms | 1000 | 心跳周期（主控覆盖为 500） |
| heartbeat_timeout_ms | 3000 | 失联判定阈值（建议 ≥ 3 倍心跳周期） |
| sync_interval_ms | 500 | 主控状态快照同步周期 |

### 3.4 `nodes` 段（每个节点）

每个节点包含：`id / role / description / ip / port`、`subscribe_topics`（订阅列表）、`publish_topics`（发布列表，文档性质）、`function_blocks`（功能块清单：type/name/params）。

**常见调整示例**：

```yaml
# 让热备更快检测主控失联（检测窗口 = timeout_ms + 100ms 巡检粒度）
nodes:
  node_e:
    function_blocks:
      - type: StandbyMonitorFB
        name: standby_monitor
        params:
          timeout_ms: 1000        # 由 1500 收紧到 1000

# 放宽视觉 NG 判定（也可运行时经 Web 在线修改，无需重启）
          ng_threshold: 0.55
```

> 修改 `nodes.yaml` 后需重启对应节点进程生效；`params` 中的参数均可在运行中通过 Web 控制台在线调整。

## 4. 启动顺序

**单机演示（7 个终端）**：

```bash
# 顺序原则：主控先就绪以接收心跳；节点间无硬依赖，顺序可调换

# 终端1 —— 主控节点（订单分解/任务调度/健康监测）
python nodes/node_a_orchestrator.py

# 终端2 —— 机器人节点（搬运/标定/轨迹规划；启动时自动上电标定）
python nodes/node_b_robot.py

# 终端3 —— PLC节点（传送带/气缸/伺服）
python nodes/node_c_plc.py

# 终端4 —— 视觉节点（采图/AI推理/缺陷分类）
python nodes/node_d_vision.py

# 终端5 —— 热备节点（状态复制/50ms接管）
python nodes/node_e_standby.py

# 终端6 —— Web 控制台
python web-ui/app.py --port 5000

# 终端7 —— 订单模拟器（持续随机下单）
python simulator/order_generator.py --interval 5
```

**一键后台启动（Linux/Git Bash 示例）**：

```bash
for n in a_orchestrator b_robot c_plc d_vision e_standby; do
  (python nodes/node_${n}.py > node_${n%%_*}.log 2>&1 &)
done
(python web-ui/app.py > web.log 2>&1 &)
```

**多主机部署**：把项目目录复制到各工控机；修改 `mqtt.host` 指向 Broker；每台机器只启动属于自己的节点进程（可删除无关节点脚本或直接忽略）；`runtime/` 目录留在本地作为诊断通道。

## 5. 验证方法

### 5.1 冒烟验证（启动后 30 秒内完成）

| 步骤 | 命令/操作 | 预期结果 |
|------|-----------|----------|
| 1. 进程存活 | 查看五个终端无报错回显 | 各节点打印"已启动"，node_b 完成上电标定（RMSE 合格） |
| 2. 集群状态 | `python simulator/fault_injector.py list` | 5 节点全部 `[在线]`，心跳 < 2s |
| 3. 控制台 | 浏览器打开 `http://localhost:5000` | 5 张节点卡片绿色，事件流滚动 |
| 4. 下单 | 控制台"手动任务下发"或 `python simulator/order_generator.py --count 1` | 主控日志出现"分解为 N 个任务"，各节点日志出现执行记录，主控"累计完成"递增 |
| 5. 心跳链路 | 观察事件流 Heartbeat | 每秒 5 条心跳（node_a 每 0.5s 一条） |

### 5.2 热备切换验证（核心验收项）

```bash
# 1) 注入主控宕机 15 秒
python simulator/fault_injector.py down node_a --sec 15

# 2) 观察 node_e 终端，预期输出：
#    【热切换完成】检测静默~1580ms 切换耗时~1.4ms（预算50ms 达标） epoch=2 恢复任务N个

# 3) 观察 node_a 终端（15秒后恢复），预期输出：
#    检测到新领导者 node_e，node_a 已让位（可重启为备用）

# 4) 切换期间在 Web 下单 -> node_e 日志出现"接管态收到订单"

# 5) 清理
python simulator/fault_injector.py clear
```

**验收标准**：切换耗时 ≤ 50ms；接管后任务继续派发执行；原主控恢复后无重复派发（让位生效）。

> 自动化回归：上述热备切换的"零重复派发"性质已固化为 `pytest tests/` 用例
> （`tests/test_failover.py`，纯共享内存通道运行，不依赖 MQTT Broker），
> 另含 ECC 迁移表、主题匹配、fencing 与队列背压等用例。

### 5.3 故障注入矩阵验证（可选）

```bash
python simulator/fault_injector.py down node_b --sec 10   # 工作节点宕机：任务回收重派
python simulator/fault_injector.py delay node_c 500        # 网络延迟：时延上升不丢单
python simulator/fault_injector.py loss node_d 0.3         # 丢包30%：重试兜底
python simulator/fault_injector.py list                    # 查看生效指令与剩余时间
python simulator/fault_injector.py clear                   # 全部清除
```

### 5.4 Web 在线配置验证

控制台 → 功能块参数在线配置 → 选择 `node_d / classifier / ng_threshold` → 输入 `0.55` → 应用。
预期：node_d 终端打印 `在线配置生效 fb=classifier params=['ng_threshold']`，事件流出现 FBConfigUpdated 回执。

## 6. 停止与清理

```bash
# 各节点终端按 Ctrl+C 优雅停止（写最终状态槽 state=stopped）
# 批量停止（Git Bash）：
ps | grep -i python | awk '{print $1}' | xargs -r kill

# 清理运行时产物（事件日志/状态槽/租约/故障指令）
rm -rf runtime
```

> 重新做切换演练前建议清理 `runtime/`，避免旧租约/旧事件流干扰（热备会从旧 bus.jsonl 重放历史心跳）。

## 7. 故障排查（FAQ）

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 节点启动即退出 `not enough values to unpack` | nodes.yaml 功能块清单与脚本 FB_REGISTRY 不匹配 | 检查对应节点 function_blocks 是否含 TaskRouterFB 等全部类型 |
| Web 打不开 / API 404 | Flask 未安装或端口占用 | `pip install flask`；换 `--port 5001` |
| 控制台全部节点"离线" | 节点未启动，或 runtime 目录被删除后 Web 先于节点启动 | 启动节点；刷新页面（状态槽会自动重建） |
| 节点互相收不到消息（单机） | runtime 目录权限异常或被杀毒软件锁定 | 检查 `runtime/bus.jsonl` 是否在增长；排除目录 |
| 热备不接管 | 主控心跳未真正停止；或旧 runtime 残留旧心跳被重放 | 确认 down 指令生效（`list` 查看）；清理 runtime 后重试 |
| 热备反复"失联/恢复"抖动 | （历史缺陷，已修复）路由串扰；若复现请升级到最新代码 | 更新 core/distributed_runtime.py |
| 切换后双主控都在派发 | 旧版本无让位暂停逻辑 | 确认 node_a 日志出现"已让位"；更新代码 |
| MQTT 连不上但系统正常 | 预期行为：双通道降级 | 安装 paho-mqtt 并启动 Broker 可启用双通道 |
| 事件流越来越大 | bus.jsonl 持续追加 | 定期归档；或 `rm -rf runtime` 重置（会丢历史） |
| Windows 下文件锁超时 | msvcrt 锁竞争异常/杀软扫描 | 重试；将项目目录加入杀软白名单 |

## 8. 生产化改造清单（超出本项目范围，仅供路线参考）

1. MQTT 启用 TLS 与用户名/密码认证，事件信封增加签名与防重放；
2. `runtime/` 租约与状态槽迁移到高可用共享存储（NFS/数据库）；
3. Web 控制台增加登录鉴权与操作审计；
4. 节点以系统服务（systemd / Windows Service）托管，配置开机自启与崩溃拉起；
5. 事件日志接入时序数据库，建立长期容量与告警基线；
6. 安全功能（急停/安全区域）由独立安全回路承担，与本系统仅做状态交互。
